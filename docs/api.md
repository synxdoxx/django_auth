# REST API — реальные маршруты

Базовый префикс `/api/` задан в `tickets/urls.py` и `labs/urls.py`. Все перечисленные API используют DRF `SessionAuthentication` и `IsAuthenticated` из `config/settings.py`. Неавторизованный запрос может получить **403**; при изменении через сессию требуется CSRF (иначе **403**). Для несуществующего объекта обычно **404**, для некорректных данных **400**. Ответы ниже иллюстрируют формат сериализаторов, а не реальные записи вашей базы.

## Категории заявок
- `GET /api/categories/` — список, без тела; пример **200**: `[ {"id":1,"name":"Учебный вопрос"} ]` (DRF может применять пагинацию, если она настроена).
- `GET /api/categories/1/` — категория по ID; **200**: `{"id":1,"name":"Учебный вопрос"}`; ошибки 403/404. Изменение категорий через этот API не реализовано (`ReadOnlyModelViewSet`, POST/PUT/PATCH/DELETE → 405).

## Заявки
- `GET /api/tickets/` — список **только собственных** заявок, фильтр `?status=new`; **200**: `[{"id":1,"title":"Нужна справка","description":"Описание","category":1,"category_name":"Учебный вопрос","status":"new","created_at":"2026-10-30T12:00:00Z"}]`.
- `GET /api/tickets/1/` — собственная заявка; **200**: объект формата выше; 403/404.
- `POST /api/tickets/` — создание собственной заявки; JSON: `{"title":"Нужна справка","description":"Описание","category":1}`; **201**: объект с `id`, `status:"new"`, `created_at`; **400**: название короче 5 символов, неверная категория или статус при создании не `new`.
- `PUT /api/tickets/1/` — полная замена полей; JSON: `{"title":"Нужна справка","description":"Обновлено","category":1,"status":"progress"}`; **200**: обновлённый объект; **400**: обязательные поля не переданы или недопустимый переход.
- `PATCH /api/tickets/1/` — частичное обновление; JSON: `{"status":"progress"}`; **200**: обновлённый объект; **400**: недопустимый переход. Допустимы `new → progress → done`.
- `DELETE /api/tickets/1/` — удаление собственной заявки, без тела; **204** без тела; **404** если чужая/отсутствует.

## Лабораторные работы
- `GET /api/labs/` — список; **200**: `[{"id":1,"title":"Лабораторная 1","free_slots":5}]`.
- `GET /api/labs/1/` — лабораторная по ID; **200**: `{"id":1,"title":"Лабораторная 1","free_slots":5}`; **404** если нет. Остальные методы не поддерживаются (405).

## Сдачи лабораторных
- `GET /api/submissions/` — список собственных сдач; у `is_staff` доступны все; фильтры `?status=new&lab=1`. **200**: `[{"id":1,"lab":1,"lab_title":"Лабораторная 1","comment":"Готово","status":"new","created_at":"2026-10-30T12:00:00Z"}]`.
- `GET /api/submissions/1/` — одна доступная сдача; **200**: объект указанного формата; **404** если недоступна.
- `POST /api/submissions/` — создать сдачу; JSON: `{"lab":1,"comment":"Готово"}`; **201**: объект со статусом `new`; одновременно создаётся Event `Работа сдана`; **400** при неверном `lab`.
- `PUT /api/submissions/1/` — полное обновление; JSON: `{"lab":1,"comment":"Исправлено"}`; **200**: обновлённый объект; **400** если сдача уже не `new`.
- `PATCH /api/submissions/1/` — частичное обновление; JSON: `{"comment":"Исправлено"}`; **200**: объект; **400** если статус не `new`. Поле `status` у сериализатора только для чтения.
- `DELETE /api/submissions/1/` — удаление, **204**; **400** если статус не `new`.
- `POST /api/submissions/1/book/` — запись на защиту, тело не требуется; **200**: сдача со статусом `booked`; **400** если статус не `new` или `free_slots` равен нулю. Число свободных мест уменьшается на 1, создаётся Event.
- `POST /api/submissions/1/accept/` — принять работу, тело не требуется; **200**: сдача со статусом `accepted`; **403** для пользователя без `is_staff`; **400** если статус не `booked`.
- `GET /api/submissions/1/history/` — история; **200**: `[{"id":1,"action":"Работа сдана","user":"student","created_at":"2026-10-30T12:00:00Z"}]`; **404** для недоступной сдачи.

## Проверка запросов
Откройте страницу `/` или `/labs/` после входа; в DevTools → Network наблюдайте реальные GET/POST/PATCH, коды ответов и повторный GET. Для изменяющих запросов браузер должен отправлять сессионную cookie и `X-CSRFToken`. Не публикуйте значения cookie или CSRF-токенов. **Важная особенность исходного кода:** в `SubmissionViewSet` сотрудники (`is_staff`) могут видеть и изменять все сдачи; у `TicketViewSet` доступ всегда ограничен владельцем. Это описание фактической реализации, не предложение изменить права.
